# Soota 项目约定

## 公开文档与本地资料

- README 是对外产品文档，只写当前能力、安装、使用、限制和许可证。禁止写内部开发计划、里程碑编号、任务进度或下一阶段安排。
- 内部计划和进度保存在项目外的 `$SOOTA_CONFIG_DIR/private/`（未设置时为 `~/.config/soota/private/`）。历史本地路径 `docs/private/`、`PLAN.md`、`PLAN.zh-CN.md` 继续保持 Git 忽略和构建排除，不得强制加入 Git、提交、上传或放进发行包。
- 公开 `docs/` 同样不得承载私人计划；允许客观说明现有功能限制、架构与验证边界。
- 发布前检查当前文档、历史 README 和发行包元数据，不能只删当前工作区的计划内容而保留在历史版本。
- 修改产品代码与配置前核对现有实现；文档清理不得改变功能行为或历史源码内容。

## 用户数据与 Skill

- 个人关注名单、账号别名、凭据、私人路径和执行规则放在项目外的用户配置或私人知识库中，不得写入源码、公开文档、测试样例或共享 Skill。示例使用通用占位符或合成测试数据，不保留个人使用记录。个人路径、账号选择和凭据由环境变量注入，仓库仅保留变量名称和读取逻辑。
- Skill 只维护通用操作流程和来源顺序；已有标准命令继续由 Soota 路由。MCP 当前默认停用；YouTube/Bilibili 字幕获取按平台和能力的 cost/manual 优先级选择；免费来源默认优先，Monid 可选启用，Monid/TikHub 均受费用策略控制。确认没有字幕轨道时结束字幕 Provider 查询，auto 直接获取音频并本地转写；未知或获取失败不能冒充无字幕。音频默认 yt-dlp，Downie 仅显式选择，TikHub 音频遵守同一次运行的剩余预算。临时任务按实际能力查找，不恢复批量 OpenCLI 命令映射。
- 采集、单项分析契约或输出约定变化时，同步检查 `skills/soota/SKILL.md` 及相关引用。个人资料库的规则与 prompt 只在本地维护，Skill 指导 Agent 从目标目录的 `AGENTS.md` 读取对应文件，不复制私人正文或路径。
- 用户数据所在目录需核对自身的 Git 与同步规则，不能把“位于项目外”当作隐私保证。

## Context 与文章

- 默认摄取到 `context.md` 即结束：只做格式解析和按原顺序提取文本，不做语义改写、润色、合段或自动摘要。
- 分析／总结请求直接使用 context；只有用户明确要求详细文章阅读或知识整理归档时才整理文章；知识任务不是普通分析的隐式前置步骤。旧目录规则或提示词不得隐式添加文章中间步骤。
- `transcript.md` 保留时间轴；阅读／分析产物与源正文分开。重新采集不覆盖已有文章，显式 render 不重写源文件。

## 处理层与文档同步

- 高层黑盒流程与模块职责以 `docs/providers.md` 的“处理流程与职责”为主源；统一任务的目标、输入、恢复、v2 产物和导出契约以 `docs/tasks.md` 为主源；跨来源知识整理、学习与交付由外部 LoreLab 负责；字幕格式与限制以 `docs/subtitle-formats.md` 的“统一转换层”为主源。
- 修改模块职责、阶段顺序、获取／转换接口、输入输出或实现能力时，同步更新受影响的职责图、入口表和格式能力表；图描述已实现状态，不能把目标或计划写成现有能力。
- Provider 只负责获取、轨道与获取格式选择、原始正文和获取状态。字幕正文解析集中在 `transcripts/formats/`，统一入口为 `transcripts/conversion.py`；编排层在转换成功后写字幕缓存。新增 Provider 不复制已有格式解析器。
- 统一任务的执行与恢复归 `tasks/`；动态发现和已核实的原生结果绑定归 `content/`；媒体下载、合并、提取与验证归 `media/`；内容包、分析校验和导出归 `artifacts/`；跨来源文章、学习、交付核对和授权清理归外部 LoreLab；`workflow_compat.py` 只转发旧命令，不保存流程。新增 Provider 或格式复用这些边界，不复制整条任务流程。
- 修改输入、`--want` 目标、采集条件、预算、任务状态、提交 schema、产物路径或导出行为时，同步核对 `docs/tasks.md`、README 命令示例、`skills/soota/SKILL.md` 及 `references/tasks.md`；职责变化同时更新高层图。文档只声明已实现行为，动态发现、契约测试和真实站点验收分别记录。
- 全批计费预留在请求发送前持久化，恢复不能清零；成功以必需产物及其验证结果判断，枚举完整性单独报告。原生读取失败不能用包元数据替代为成功的数据产物。
- 语义分析只在用户明确请求后接续；提交须校验正文指纹和证据 ID，任务恢复还须核对 task/item 身份。采集保留已有分析或文章，来源变化标记过时。知识库导出只写显式目的地并保护人工修改，不自行推断分类或重组知识库。

## 与 LoreLab 的职责边界

- Soota 负责正文与媒体采集、解析、context、预算、缓存和采集任务恢复。单项分析提交与内容包导出契约保留，程序不自行生成语义内容。
- 跨来源文章整理、学习大纲、交付核对与授权清理由 LoreLab 及其 Skill 维护；不在 Soota 重建工作流或复制提示词。
- 旧 `soota knowledge/study` 通过 `workflow_compat.py` 原样转发到已安装的 LoreLab，普通帮助不展示；受管安装缺失时停止，不误用其他产品版本。独立采集不依赖 LoreLab，组件源码与 Skill 引用须自含。
- 已有采集任务仍用 `soota jobs`；已有知识任务通过 LoreLab 按原绝对路径恢复，冻结来源、指纹和清理条件不变。`lorehub` 命令继续保持移除，历史配置和环境变量由 LoreLab 兼容读取。
