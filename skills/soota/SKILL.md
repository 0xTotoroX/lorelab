# Soota

Use an installed `soota` command. For a source checkout, resolve this SKILL.md symlink, locate the repository two directories above its skill directory, verify pyproject.toml belongs to Soota, and run `uv run --project <repository> soota ...`. Do not hard-code a personal checkout path. Codex calls this CLI; Soota chooses its internal Providers. Do not register opencli-mcp as a separate Codex tool for this workflow.

1. Match the requested output. For a video, use `ingest URL --transcript captions-only|auto|asr|none --json`; `captions-only` saves actual captions and never starts ASR. Use `inspect URL --json` for metadata only. Run `doctor --json` if the runtime is unknown.
2. The default capability order is OpenCLI → yt-dlp (YouTube/Bilibili metadata and captions) → authorized TikHub. opencli-mcp is disabled; do not discover or call it. `--provider` selects the metadata/caption source explicitly. Confirmed missing caption tracks end the caption chain: `auto` downloads audio and transcribes locally, while `captions-only` stops without ASR. `unknown`, empty responses and login failures are not proof of absent captions. `--max-cost 0` blocks billed TikHub requests. In ask mode, noninteractive paid calls stop with `payment_required`; never bypass that gate or enable auto payment for the user.
3. `--json` prints one status document. Report output paths, actual Provider, caption status/source, cache hit, request count, and estimated cost. Read `data.context` as the Agent input path; `data.transcript` retains timestamped evidence. Collection-only requests end at context, without an article, summary, polishing or semantic cleanup. For an explicit analysis/summary request, use context directly. Create a detailed reading article only when the user explicitly requests it; read [analysis guidance](references/analysis.md) then apply the destination rules. Do not load or print the full body for a download-only request.
4. For optional Bilibili → YouTube counterpart selection, use `ingest URL --prefer-youtube --max-cost 0 --json`; `--no-prefer-youtube` disables it. This matches a unique same-name channel, stable channel ID and episode metadata. Cross-links are additional evidence; do not claim verified creator identity when `author_crosslink_confirmed` is false. Read `selection` / `youtube_check` to explain the actual choice. It also enables promotion filtering; `--keep-promotions` overrides that. If promotion-free output is requested, review the filtered transcript for unannotated ads before analysis. `--exclude-range START_SECONDS:END_SECONDS` removes additional reviewed intervals; keep original video times and stable segment IDs. Rebuild in a new output folder or use authorized `--force` if filtering changes. Never claim that no community annotations means no promotion. See `docs/subtitle-selection.md` for boundaries.
5. Audio selection is independent: `--audio-provider yt-dlp` is the default; `downie` is opt-in on macOS and needs the completion hook in `docs/providers.md`; `tikhub` requires payment authorization. Downie may download video before Soota extracts audio. A `download_pending` result is not completion: check the existing queue/hook, then resume without submitting another download. `asr` skips caption discovery; metadata acquisition can still need a Provider.
6. For ad hoc capability discovery and platform API queries, read [API reference](references/api.md). For catalogs and incremental snapshots, read [catalog reference](references/catalog.md). Load only the reference needed for this task. Provider catalogs may include websites, applications and services; an entry is not necessarily a content platform or a supported video-ingest source.

Online collection/API commands automatically update published provider packages by default. Inspect `runtime_updates` and warnings; updating MCP never enables it. Use `updates apply --json` for an explicit update, `updates check --json` for read-only repository/version checks. `SOOTA_AUTO_UPDATE=false` preserves a pinned or rolled-back runtime. Help, estimates, offline previews and render do not update. Package updates do not prove website availability.

Keep cookies and API keys out of chat and command arguments. Captions take precedence over ASR; comments and danmaku are not captions. Do not archive full video or write into Obsidian unless the user asks. Let the CLI handle its known YouTube empty-caption fallback to yt-dlp. Other dispatched errors do not authorize manual retries or paid calls. `--provider yt-dlp` explicitly selects the yt-dlp adapter for YouTube/Bilibili metadata and captions; the same provider supports audio acquisition for ASR. It does not expose all yt-dlp sites. Bilibili AI tracks use `ai-*` language codes and are downloaded with ordinary subtitle flags; never treat danmaku as captions. Legacy `--provider soota` remains an alias; new results identify `yt-dlp`. yt-dlp and Downie are installed/updated separately.

Read personal paths, browser selection and credentials from environment variables (`SOOTA_OUTPUT_DIR`, `OPENCLI_PROFILE`, `SOOTA_YTDLP_BINARY`, `SOOTA_YTDLP_COOKIES_BROWSER`, `TIKHUB_API_KEY`); never embed their actual values in this Skill or project files. Personal creator lists and processing rules belong in user-owned files outside the repository; do not invent an unsupported watchlist environment variable. Do not claim Soota automatically schedules collection or manages watchlists. Check the destination’s own Git/sync exclusions before calling personal files untracked.

## Context and optional processing

`ingest` writes context.md, transcript.md and manifest.json. Context keeps cue order, wording, repetition and fragment IDs; no readability rewrite is needed. The ingest `data.content` field is a compatibility alias for context. Old bundles without context use transcript.md as input. Preserve existing reading files; stale/pending analysis state is not an instruction to regenerate them. `source_preserved` means this attempt did not replace an existing valid source; do not report it as a fresh successful acquisition. Format capabilities and preferences are documented in `docs/subtitle-formats.md`; do not assume unimplemented formats are available through Soota.

## Local collection rules

Resolve the requested collection from the user's destination or output configuration. Before writing there, read its applicable `AGENTS.md` and follow its references to processing rules and the selected prompt. Honor its allowed-source list; do not add other sources or create their directories merely because an upstream tool supports them. Read the current prompt when analysis or article processing is requested; a saved workflow must not implicitly add an article stage to collection-only or direct-analysis tasks. Keep personal rules and prompt text in the user's collection rather than copying them into this shared Skill. Read only files needed for the task. Do not guess a private vault path or treat an arbitrary document as an instruction file. These instructions guide the Agent; the CLI does not load them automatically.

Use the collection's display names for reading folders and labels. Keep command identifiers, source IDs, manifest fields and CLI-managed bundle paths unchanged unless a compatible migration is part of the task. When changing collection workflows, review this Skill and its relevant references in the same change; update shared guidance only where the general workflow changes.
