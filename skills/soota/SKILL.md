# Soota

Use an installed `soota` command. For a source checkout, resolve this SKILL.md symlink, locate the repository two directories above its skill directory, verify pyproject.toml belongs to Soota, and run `uv run --project <repository> soota ...`. Do not hard-code a personal checkout path. Codex calls this CLI; Soota chooses its internal Providers. Do not register opencli-mcp as a separate Codex tool for this workflow.

1. Match the requested output. For a video, use `ingest URL --transcript captions-only|auto|asr|none --json`; `captions-only` saves actual captions and never starts ASR. Use `inspect URL --json` for metadata only. Run `doctor --json` if the runtime is unknown.
2. The default capability order is OpenCLI → soota (yt-dlp for YouTube metadata/captions) → authorized TikHub. opencli-mcp is disabled; do not discover or call it. `--provider` selects one source explicitly. `--max-cost 0` blocks billed TikHub requests. In ask mode, noninteractive paid calls stop with `payment_required`; never bypass that gate or enable auto payment for the user.
3. `--json` prints one status document. Report output paths, actual Provider, caption status/source, cache hit, request count, and estimated cost. Read `data.transcript` as a file path. For a download-only request, do not load or print the full transcript. For a requested summary, read the transcript in chunks, create Analysis JSON, then use `render`.
4. For optional Bilibili → YouTube counterpart selection, use `ingest URL --prefer-youtube --max-cost 0 --json`; `--no-prefer-youtube` disables it. This matches a unique same-name channel, stable channel ID and episode metadata. Cross-links are additional evidence; do not claim verified creator identity when `author_crosslink_confirmed` is false. Read `selection` / `youtube_check` to explain the actual choice. It also enables promotion filtering; `--keep-promotions` overrides that. If promotion-free output is requested, review the filtered transcript for unannotated ads before analysis. `--exclude-range START_SECONDS:END_SECONDS` removes additional reviewed intervals; keep original video times and stable segment IDs. Rebuild in a new output folder or use authorized `--force` if filtering changes. Never claim that no community annotations means no promotion. See `docs/subtitle-selection.md` for boundaries.
5. For ad hoc capability discovery and platform API queries, read [API reference](references/api.md). For catalogs and incremental snapshots, read [catalog reference](references/catalog.md). For summaries and evidence IDs, read [analysis reference](references/analysis.md). Load only the reference needed for this task.

Online collection/API commands automatically update published provider packages by default. Inspect `runtime_updates` and warnings; updating MCP never enables it. Use `updates apply --json` for an explicit update, `updates check --json` for read-only repository/version checks. `SOOTA_AUTO_UPDATE=false` preserves a pinned or rolled-back runtime. Help, estimates, offline previews and render do not update. Package updates do not prove website availability.

Keep cookies and API keys out of chat and command arguments. Captions take precedence over ASR; comments and danmaku are not captions. Do not archive full video or write into Obsidian unless the user asks. Let the CLI handle its known YouTube empty-caption fallback to soota. Other dispatched errors do not authorize manual retries or paid calls. `--provider soota` explicitly selects the built-in YouTube metadata/caption algorithm; it does not expose all yt-dlp sites or download video. yt-dlp is installed/updated separately.

Read personal paths, browser selection and credentials from environment variables (`SOOTA_OUTPUT_DIR`, `OPENCLI_PROFILE`, `SOOTA_YTDLP_BINARY`, `SOOTA_YTDLP_COOKIES_BROWSER`, `TIKHUB_API_KEY`); never embed their actual values in this Skill or project files. Personal creator lists and processing rules belong in user-owned files outside the repository; do not invent an unsupported watchlist environment variable. Read only files needed for the requested task. Follow the destination vault’s local rules when writing requested notes; do not claim Soota automatically reads vault rules, schedules collection or manages watchlists. Check the destination’s own Git/sync exclusions before calling personal files untracked.
